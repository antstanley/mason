## Steps

- [ ] Add `FeedTarget<'_>` as `Actor(&str)` or `Feed(&str)` and change `handle_feed` to take it. The demo short-circuit stays on the `Actor` arm.
- [ ] Put the selection rule in **mortar-core**, not in either front:
      `pub fn FeedTarget::from_query<'a>(actor: Option<&'a str>, feed: Option<&'a str>) -> Result<FeedTarget<'a>, AppError>`
      in `feed.rs`, holding both halves of the rule (`feed` wins when both are
      present, neither present is the `bad_request`). An explicit lifetime, not
      `'_`: two input references cannot elide into one output lifetime. Give it
      `pub fn kind(&self) -> &'static str` returning the wire token for the arm
      (`"actor"` or `"feed"`), which is the vocabulary task 14 pins. Neither
      front may spell the rule out itself: `mortar-server` has no test module,
      so a copy there ships untested, and `tests/contract.rs` is a mortar-core
      integration test that can reach neither front crate.
- [ ] Factor `resolve_did` out of `resolve_and_gate` (the cold-handle branch minus the gate) so a `bsky.app` feed URL can resolve its profile segment without inheriting the wall-owner gate. `resolve_and_gate` keeps calling it.
- [ ] Add the `feed_wall` path, called before `resolve_and_gate`: parse the reference, decode the cursor, read `feed_page_cached`, filter for glaze, and answer. `Mode::Wall` asks `getFeed` for `PAGE_SIZE`; `Mode::Glaze` asks for a named 100 constant, filters `is_image_post`, and lays **every** survivor rather than truncating.
- [ ] Fix the wasm export's argument order once, here: `feed_page(actor, feed, cursor, mode, intent)`, all `Option<String>`. Add `feed` to `FeedParams`. Both fronts then **call `FeedTarget::from_query`** and map its `Err` into their own envelope rather than each spelling the precedence and the missing-parameter case out: the axum route's `ok_or` at `:42` goes away entirely, and the wasm export drops its own guard. Read and forward `?feed=` in the service worker, relaxing the `!actor` guard so it fires only when **both** are absent, and update its hardcoded copy of the message at `:254`.
- [ ] Change the canonical `bad_request` instance in `error.rs`'s test module to the new literal, updating `variants()` at `:75` and both pinned envelope arrays at `:90` and `:106` together, so the strings the wasm front and the axum front are pinned to are strings mortar still emits. **Leave `tests/contract.rs`'s `errors()` alone**: it feeds `contract.json`, and editing it here would make `cargo test` red until a regeneration this task is not allowed to do. Task 14 owns that half, inside its regeneration, and the fixture pins the older wording for exactly one task.
- [ ] Add wiremock tests for the feed wall that mock only `getFeed` and `getProfile`, and a Playwright case for the two offline 400s.
- [ ] Add a second Playwright case, `the service worker binds every positional slot`, which is the **only** lane that can see an argument transposition (task 00's tsc project counts arguments, it cannot read their order). Entirely offline on the demo wall: fetch `/api/feed?actor=demo&mode=glaze`, keep its `cursor`, then fetch `/api/feed?actor=demo&mode=glaze&intent=preview&cursor=<that cursor>` and assert three independent things about the answer. Every item is `kind === 'post'` (the `mode` slot: `demo_page` filters to `is_image_post` under glaze, and the fixture pool is 70/15/15 post/blog/video, so a wall page carries blogs and videos). `warming === false` (the `intent` slot: `feed.rs:60` sets it only on a demo preview). The returned `cursor` is byte-identical to the one sent (the `cursor` slot: the demo preview branch at `feed.rs:64` re-encodes the **incoming** offset, so a cursor read from the wrong slot decodes to nothing and comes back as offset 0). The `actor`/`feed` pair needs no assertion of its own: transposed, `feed` would be `"demo"`, `FeedRef::parse` would reject it, and the first fetch would be a 400.

## Definition of done

- [ ] The precedence rule is a **mortar-core unit test over `FeedTarget::from_query`**, not a claim repeated in two crates: `feed` wins when both are present, neither present is a `bad_request` whose message names both, and an unparseable `feed` is a `bad_request` that never falls back to laying somebody's graph, each its own negative-space case. `grep -n 'BadRequest' server/crates/mortar-server/src server/crates/mortar-wasm/src` shows neither front constructing the missing-parameter error itself, which is what keeps the rule testable at all: `mortar-server` has no `#[cfg(test)]` module.
- [ ] A feed wall touches nothing in `algo/` except the cursor: no `ensure_snapshot`, no `get_or_build`, no mixer, asserted by a wiremock wall that mocks only `getFeed` and `getProfile`. `resolve_did` carries no owner gate and `an_opted_out_owner_seals_their_wall` passes unchanged.
- [ ] A wiremock feed wall proves: upstream order preserved, a repost dropped, an opted-out author's post dropped, the wall ending when `getFeed` returns no cursor, a preview reporting `warming: false` and echoing the incoming cursor, and glaze laying only image posts without truncating to `PAGE_SIZE`.
- [ ] The message exists in one Rust place and one TypeScript place: `FeedTarget::from_query`'s `Err` arm, and `service-worker.ts:254`'s hardcoded copy, changed together because nothing in the repo compares them. `error.rs`'s canonical instance and its two pinned envelope arrays carry the same wording; `tests/contract.rs`'s `errors()` follows at task 14, and the one-task window where the fixture pins the older wording is named in the PR.
- [ ] Playwright: `/api/feed?feed=nonsense` answers 400 `bad_request` and `/api/feed` with neither parameter answers 400, both entirely offline because a malformed reference is rejected before any network call.
- [ ] Playwright: the positional-slot case above is green, and its three assertions are independent, so it fails on any adjacent transposition of `feed`, `cursor`, `mode` or `intent` rather than only on the arity. This is the whole of the ordering coverage; nothing else in the repo can see it.
- [ ] Meets the repo definition of done, plus the explicit `just wasm && cd web && pnpm check:ci` run. Task 00 is what makes that run mean anything: before it, `web/.svelte-kit/tsconfig.json` excluded `src/service-worker.ts`, so the call site was in **no** tsc program and neither a fresh nor a stale `pkg/` was being compared against. After task 00 the call is in the worker project, `check` still does not run `just wasm`, and the gitignored `pkg/` is therefore still stale unless this command is run by hand. The tsc project counts the arguments; the Playwright case above reads their order.
- [ ] Reviewable: `just dev-server`, then `curl 'localhost:8787/api/feed?feed=at://did:plc:z72i7hdynmk6r22z27h6tvur/app.bsky.feed.generator/whats-hot'` returns a page in the feed's own order.
